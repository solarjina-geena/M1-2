# Firestore 임시 내보내기 입력 폴더

백엔드가 임시자료를 찾는 위치는 프로젝트 루트의 `firestore_import/`뿐입니다. 다른 폴더는 자동 검색하지 않습니다.

## 임시 CSV 조회

- Firestore 조회를 항상 먼저 시도합니다. Firestore가 `429 RESOURCE_EXHAUSTED` 또는 일시적 서비스/네트워크 시간초과를 반환할 때 `20260801-20260930_firestore_unified.csv`를 임시 읽기 자료로 사용합니다.
- 이 CSV는 전체 스냅샷이 아니라 `ADD`, `ENRICH`, `CORRECT` 변경 목록입니다. 백엔드는 메모리에서만 순서대로 재구성하며 Firestore에 업로드하지 않습니다.
- `ENRICH`만 있고 기본 `ADD` 문서가 없는 4개 문서는 만들지 않고 제외합니다. `CORRECT`는 기대 원본과 맞거나 ADD에 이미 정정값이 들어 있는 경우만 반영합니다. 둘 다 맞지 않으면 임시조회 전체를 오류로 중단합니다.
- 임시조회 중 `data` 등록·수정·삭제는 막습니다. 대화 기록은 Firestore에 쓰지 않고 메모리에만 둡니다.
- Firestore 읽기 재시도는 60초 간격으로 하며, 읽기가 복구되면 자동으로 Firestore 자료로 돌아갑니다.

## Excel 파일

`M3-1_원본판독_9월_완성본.xlsx`는 Firestore CSV와 구조가 다른 9월 원본 판독 작업표입니다. 현재 백엔드는 이 파일을 자동으로 읽거나 CSV에 합치지 않습니다. 원본 대조용으로만 유지합니다.
